# Регламент монтажа — IMIGO.AI

Справочный файл для нового чата с Claude Code. Прикрепи его в начале сессии —
и не придётся заново объяснять стиль, цвета, шрифты и правила монтажа.
Технологический стек: **Remotion** (React), рендер через `npx remotion render`.

> ## ⚠️ СТОП: проверка шрифтов перед началом работы
>
> Прежде чем приступать к любому монтажу, **проверь**, есть ли в проекте
> (`public/fonts/`) эти 3 файла:
>
> - `InterTight-Bold.ttf`
> - `InterTight-Black.ttf`
> - `NeueMachina-Ultrabold.otf`
>
> Если хотя бы одного из них нет (например, это новый/пустой проект) —
> **останови работу и попроси пользователя прикрепить эти файлы по именам**
> выше, прежде чем продолжать. Не пытайся подобрать похожий системный шрифт
> вместо них — фирменный стиль держится именно на этих шрифтах.

> ## 🖼️ Визуальные примеры из регламента
>
> Оригинальные страницы регламента IMIGO.AI (с примерами расположения субтитров,
> заголовков и цветовой палитры) сохранены как картинки в
> `docs/reglament_reference/page-1.png` … `page-7.png`. Если нужно свериться с
> точным визуальным примером (не только с текстовым описанием ниже) — открой эти
> файлы через Read. В новом/пустом проекте этой папки не будет — тогда попроси
> пользователя прислать эти скриншоты (или сам PDF регламента) заново.

## 1. Фирменная айдентика

### Цвета (использовать ТОЛЬКО эти, без выдумывания новых)
| Название | HEX | Назначение |
|---|---|---|
| Светлый | `#ECECEC` | основной цвет текста/субтитров |
| Тёмный | `#080B17` | фон, тёмные плашки, тёмные версии анимаций |
| Синий | `#2355F6` | акцент, градиенты, иконки |
| Фиолетовый | `#6056E7` | акцент, градиенты (обычно синий→фиолетовый) |

Небольшой отход от палитры допустим только в второстепенных деталях.
Фоны — не изобретать сложные фирменные фоны, использовать фон исходника
(или фирменный тёмный `#080B17` для полноэкранных анимационных вставок).

### Шрифты
- **Neue Machina** (Light / Regular / Ultrabold) — только для небольшого объёма текста
  (логотипы, короткие бейджи). **Осторожно:** в Ultrabold встречается кривая отрисовка
  кириллической буквы «И» (проверено на рендере) — если текст на кириллице выглядит
  странно, переключайся на Inter Tight Black/ExtraBold, это надёжный вариант.
- **Inter Tight Bold** — основной шрифт субтитров. Титры — **КАПСОМ**.
- Другие начертания Inter Tight (Black, ExtraBold, SemiBold, Medium, Regular, Light,
  Italic) — для нестандартных заголовков/акцентов.

**Нужные файлы шрифтов** (кладутся в `public/fonts/` проекта):
- `InterTight-Bold.ttf` — основной, для субтитров
- `InterTight-Black.ttf` — для крупных заголовков/обложек
- `NeueMachina-Ultrabold.otf` — для лого/бейджей (см. предупреждение выше)

В ЭТОМ проекте (`video/`) они уже лежат на месте — пересылать не нужно.
Если начинаешь **новый/пустой проект в другом чате** и берёшь только этот MD —
markdown не может нести внутри себя бинарные файлы шрифтов, так что просто
прикрепи эти 3 файла заново (у себя они, скорее всего, лежат в папке `C:\Шрифты`
или там, откуда брал в прошлый раз) — этого достаточно, всё остальное код
настроит сам по инструкциям ниже.
- Иностранные слова и названия сервисов — латиницей (Reels, Stories, Instagram,
  Telegram, YouTube, Shorts, Remotion, Claude и т.п.).

## 2. Субтитры (word-level captions)

### Как получать тайминги — ОБЯЗАТЕЛЬНО реальная транскрибация
Не использовать «на глаз»/пропорциональные оценки по длине слова — это даёт
заметный дрейф синхронизации на длинных фразах. Порядок действий:
1. Извлечь аудио в 16kHz mono WAV (`ffmpeg -i video.mp4 -ar 16000 -ac 1 audio.wav`).
2. Прогнать через Whisper (`@remotion/install-whisper-cpp`), модель **`small`**
   (не `medium` — большая модель часто рвёт соединение при скачивании).
   Обязательно `language: "Russian"`, `tokenLevelTimestamps: true`.
3. Whisper отдаёт **суб-токены** (куски слов), не целые слова. Нужно склеить их в
   слова: токен с ведущим пробелом = начало нового слова, без пробела = продолжение
   предыдущего (плюс знаки препинания приклеиваются к предыдущему токену).
4. Whisper иногда **сливает границу слова с соседней паузой в звуке** (типичная
   ошибка на связках типа «...субтитры, но ещё...»). Если тайминг слова выглядит
   подозрительно (текст «наезжает» на паузу) — перепроверь через
   `ffmpeg -af silencedetect=noise=-32dB:d=0.05` в этом промежутке и подгони границы
   под реальные паузы в звуке.
5. Исправляй опечатки/неправильно распознанные слова Whisper вручную (текст),
   но **тайминги (startMs/endMs) бери из реальной ASR**, а не выдумывай.

### Отображение
- Группировка слов в «страницы» — `createTikTokStyleCaptions` с
  `combineTokensWithinMilliseconds: 550`.
- Появление — **простой кроссфейд ~100мс** (fade in/out). Никаких pop/bounce/scale-
  эффектов на смене субтитров — по фидбэку это выглядит дёргано.
- Текст: Inter Tight Bold, **КАПС**, без теней. Если на фоне не хватает контраста —
  тёмная плашка позади текста (радиальная/линейная маска с растушёванным краем),
  не грубая тень.
- Убирать запятые из отображаемого текста субтитров (точки — можно оставлять).
- Позиция по умолчанию: у подбородка/груди спикера, одна строка,
  `paddingTop ≈ 52% высоты кадра` (подбирать по факту под конкретное видео —
  смотреть, куда попадает подбородок на кадре).
- Во время полноэкранных анимационных вставок субтитры можно приподнимать/опускать
  индивидуально под конкретную сцену, лишь бы не пересекались с графикой.

## 3. Полноэкранные анимационные вставки

Когда нужно показать инфографику/анимацию поверх ролика:
- Либо накладывать анимацию поверх видимого исходника (как маленькие
  чипы-иконки), либо **полностью скрывать видео тёмным фоном** (`#080B17`),
  оставляя звук и субтитры — по запросу пользователя, уточнять какой вариант нужен.
- Стиль графики — минималистичный, неоновый: тонкие линии, свечение
  (`filter: drop-shadow`), фирменный градиент синий→фиолетовый.
- Вход/выход анимации не должен перекрывать субтитры — либо анимация в верхней/
  центральной трети экрана, либо субтитры на это время сдвигаются.
- Если попросят стилизованный переход (например «появление через пиксели») —
  реализуется через `mask-image` с сеткой мелких `<rect>` (data-URI SVG),
  включая обратный вариант (эффект должен уметь идти и в конце сцены, симметрично).

## 4. Скринкасты
Если в исходниках уже есть готовый скринкаст сервиса — использовать его.
Если нет и просят «любой скринкаст» — можно сделать стилизованный минималистичный
мокап (код/интерфейс в фирменных цветах), не имитируя дословно чужой реальный UI.

## 5. Звук
- Голос всегда доминирует, шумы/причмокивания — чистить.
- Музыка (если есть) — только инструментал (кроме мемов), тише голоса.
- Звуковые эффекты для анимаций — не брать из платных библиотек. Можно
  синтезировать простые UI-звуки (поп/вуш/тик/клик) напрямую через генерацию
  PCM-сэмплов (синус с огибающей, отфильтрованный шум) — быстро, без вопросов
  с лицензиями, звучит чисто для минималистичного стиля.

## 6. Призыв в конце (CTA)
Три варианта в зависимости от площадки:
- **Instagram RU** — призыв написать кодовое слово + отсылка на закреплённый ролик.
- **Instagram ENG** — призыв написать кодовое слово для получения ссылки на сервис.
- **Shorts** — призыв посмотреть туториал/обучение на канале.
Если ролик короткий (хук/сегмент до ~10 сек) — CTA обычно не нужен, это не
полноценный ролик.

## 7. Лого и бренд-элементы
- Логотип Claude/Remotion — использовать только реально присланные пользователем
  файлы (проверять alpha-канал на прозрачность, при необходимости убирать
  сплошной фон через `ffmpeg colorkey`). Не выдумывать/не искать логотипы самому.
- Бейдж «Claude × Remotion» — типовой паттерн: иконка + текст + × + второй логотип,
  в скруглённой полупрозрачной плашке.

## 8. Технические грабли (Remotion), чтобы не наступать повторно

- **`AbsoluteFill` в Remotion по умолчанию `flexDirection: column`.** Это значит:
  `justifyContent` управляет **вертикальным** позиционированием, а `alignItems` —
  **горизонтальным**. Лёгкая ловушка, если по привычке думать как про flex-row.
- Исходники с айфона часто в **HEVC (H.265)** — headless Chromium в Remotion его
  не декодирует. Перекодировать в H.264 перед использованием
  (`ffmpeg -i in.mov -c:v libx264 -crf 18 -c:a aac out.mp4`).
- CSS-паддинги в процентах считаются от **ширины** контейнера даже для
  `padding-top/bottom` — если нужна позиция в процентах от высоты, использовать
  числовое значение в пикселях (`height * 0.5`), не строку `"50%"`.
- Рендер в хорошем качестве: `npx remotion render ... --crf 16` (меньше = выше
  качество).
- Для рендера нескольких версий одного ролика (например с голосом/без) — заводить
  проп в компоненте (`voiceVolume`, `showOutroCTA` и т.п.) и передавать через
  `--props '{"key":"value"}'` при рендере, не дублировать композиции без надобности.
- Кастомные шрифты — грузить через `@remotion/fonts` `loadFont()` и обязательно
  дожидаться его в `calculateMetadata`, иначе на первых кадрах текст может
  отрисоваться системным шрифтом.
